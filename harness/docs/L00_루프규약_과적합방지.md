# L00 — 루프 규약: 과적합 방지와 탈출 조건 (2026-10-07, 측정 전 고정)

지시: wiki2 3,000건에 맞추지 말 것. **실제 검색 품질이 오른다는 것이 반복 검증으로 확실할 때만** 루프를 끝낼 것.

## 1. 무엇을 끌어올리는가 — 제품 형태로 잰다

1~5차는 "그래프 단독 vs 벡터 상한"을 쟀다(H1 실패). 실제 검색은 하이브리드다. 루프의 판정 대상은:

- **기준 V-LLM**: 제품 검색 API 상위 40청크 → 로컬 판독기(qwen3:8b)가 답
- **후보 HYB**: 같은 40청크 + **그래프 질의 결과(항목 목록과 출처 문서)** → 같은 판독기가 답.
  계획기가 질의를 세우지 못하거나 그래프 결과가 0이면 그래프 블록 없이(=V-LLM과 동일 입력)

같은 판독기·같은 청크라서 차이는 **그래프 블록에서만** 온다. 상한이 아니라 **실제 답**을 채점한다.
H1 의 +0.15(그래프 단독) 기준은 실패로 남기고, 아래는 별도 가설 **H3(하이브리드가 실제 답을 개선한다)** 의 기준이다.

## 2. 데이터 분할 — 보는 곳과 판정하는 곳을 떼어 놓는다

| 분할 | 데이터 | 용도 | 허용 |
|---|---|---|---|
| DEV | wiki2 중 doc 해시 mod 6 == 0 (486문서) | 실패 분석·기제 설계·설정 선택 | 개별 문서·출력 열람 가능 |
| EVAL | wiki2 벤치 v1 (210문항, sha 9f463341710c0bbc) | 차수별 측정 | **집계 수치만** — 평가 문서의 실패 사례로 처치를 만들지 않는다 |
| **HOLDOUT** | mixed20k 한국어 위키 리드 10,000건 중 해시 표본 3,000(wiki2 와 제목 겹침 0) + 같은 생성기로 만든 새 벤치 | **탈출 판정 전용** | EVAL 통과 후보만 실행. 결과 외 열람 금지. 실행 3회마다 남은 7,000건에서 새 홀드아웃으로 교체 |

- 홀드아웃 벤치·그래프·벡터 색인은 처치 설계 **전에** 만들고 해시를 기록한다.
- 모든 설정(스위치·임계값·프롬프트)은 **코퍼스와 무관하게 하나**다. 코퍼스별 조정 금지.
- 처치는 "한국어 문서 일반의 기제" 로 정당화해야 한다(§6-1 자문: 이 자료가 아니어도 필요한가).

## 3. 탈출 조건 (모두 충족)

1. EVAL 과 HOLDOUT **둘 다**: HYB − V-LLM 구조형 평균 Δ ≥ **+0.05**, 쌍 부트스트랩 95% CI 하한 > 0
2. 단순 조회(L) 회귀 없음: Δ ≥ −0.03
3. 재현: 같은 설정 재실행에서 점수 동일(temperature 0, seed 0 — 다르면 분산을 보고 기준 재평가)
4. 측정 유효성: 양성 대조(HYB+오라클 그래프 > V-LLM) · 음성 대조(HYB+위약 그래프 ≈ V-LLM) 동시 충족

하나라도 미달이면 루프를 계속한다. 미달 상태로 끝내야 하면 "검증 실패" 로 기록한다.

## 4. 한 바퀴의 순서

1. DEV 에서 손실 분해 → 표적 1개 → 공시(예상 Δ 포함) 커밋
2. 구현(ontokit 은 env opt-in, 기본 경로 불변·테스트 통과)
3. EVAL 측정 → 문서화·커밋
4. EVAL 이 §3-1 을 충족하면 HOLDOUT 실행(사용 횟수 기록) → 충족이면 §3 전체 확인 후 탈출, 미달이면 1로

## 5. 아직 못 덮는 것 (명시)

- 도메인: 홀드아웃도 백과체다. 뉴스·상품·정책 문서는 기계적 정답원이 없어 이 루프로 검증되지 않는다 — 별도 과제.
- 판독기는 로컬 8B 다. 제품의 합성 모델(상용 LLM)에서 같은 차이가 나는지는 미측정.

## 7. 정정 (L1 측정 전, 2026-10-07) — 실행 시간

- 판독 백엔드: Ollama(문항당 211초) → **MLX `mlx-community/Qwen3-8B-4bit`**(146초, 같은 모델·같은 4비트 계열). 판독 조건(40청크·600자) 불변.
  L1 의 Ollama 부분 실행 69문항은 `results/L1_eval_ollama_partial.json` 으로 보존 — 환경(런타임) 차이 비교용.
- 대조군 팔(HYB:oracle·HYB:placebo)은 **형태별 고정 부분표본**(`harness/bench/wiki2_bench_ctrl60.json` 68문항, 각 형태의 i mod 7 < 2)에서만 잰다.
  대조군의 목적은 장치 유효성 확인이라 전 표본이 필요 없다. 판정 팔(VLLM·HYB:ontokit_*)은 210문항 전부.
- 환경 병렬: `--shard i/n` 으로 문항을 나눠 로컬 MLX·DGX vLLM 에 분산할 수 있다. 섞어 쓸 경우 겹침 표본으로 환경 차이를 별도 보고한다.

## 8. HOLDOUT-1 실행 규약 (실행 전, 2026-10-07 23시)

- 판독기: **DGX vLLM `Qwen/Qwen3-8B-FP8`**(SSH 터널). EVAL(L1)은 로컬 MLX 4비트였다 — 같은 Qwen3-8B 계열, 런타임·양자화가 다르다.
  비교는 문항 안 쌍 차이(같은 문항의 팔들은 같은 판독기)라 판정은 유효하다. 런타임 차이는 EVAL 겹침 표본
  (`harness/bench/wiki2_bench_envoverlap.json`, 각 형태 i mod 7 == 3)을 DGX 로 다시 재서 따로 보고한다.
- 병렬: `--shard i/3` 3갈래 동시(vLLM max-num-seqs 4).
- 팔: VLLM · HYB:ontokit_r5(LLM-free, 5차 설정 고정) 210문항 + 대조군(VLLM · HYB:oracle · HYB:placebo) 고정 부분표본
  (`harness/bench_sealed/wikiH_bench_ctrl.json`). 로컬 LLM 추출 그래프(h2)는 홀드아웃에 없다(빌드 12시간) — 이번 홀드아웃은 LLM-free 후보만 판정.
- **EVAL(L1, 파서 수정 후) 판정 전에는 HOLDOUT 결과를 열지 않는다.** EVAL 이 미달이면 이 실행은 사용 1회로 세고 해석하지 않는다.
- 사용 횟수: 1 / 3 (이 실행)

## 11. 2바퀴 공시 (계산 전, 2026-10-08 17시)

- **측정 도구 수정(L01 §3)**: 위약을 placebo2(모든 사실을 원래와 다른 것으로 — 원사실 잔존 0, 타입 잔존 0)로 교체.
  구 위약은 재현용으로 보존(`placebo`). 이후 음성 대조는 placebo2 로 판정한다. EVAL·HOLDOUT 대조군 부분표본에서 재측정 중.
- **표적**: 판독기가 그래프 답을 버린다 — EVAL 집계: E1 그래프 단독 0.305 > 하이브리드 0.281, R 0.231 > 0.221.
- **처치 MERGE**(LLM 재호출 없음, 결정적 후처리): 목록 질문 = 판독기 답 ∪ 그래프 결과, 개수 질문 = 그래프 결과가 있으면
  그 개수, 없으면 판독기 개수. 계획·그래프 결과는 저장된 계획으로 재계산(SPARQL). 도메인 무관 기제.
- **예상(EVAL)**: MERGE − VLLM 구조형 ≥ **+0.08**, CI 하한 > 0. 조회(L)는 그래프 결과가 섞여 하락 위험 — §3-2 로 감시.
- 판정은 §3 그대로. EVAL 충족 시 HOLDOUT-1 에 적용(사용 2/3) — 판독 원자료가 이미 있어 추가 판독 없음.
- 알려진 한계: 저장된 판독 답은 문항당 60개까지라 큰 정답 집합에서 판독기 몫이 잘려 있을 수 있다(MERGE 에 불리한 방향).
