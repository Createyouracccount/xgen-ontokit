# D1 — 현행 XGEN 제품 그래프에 하네스를 붙이다(스키마 발견 모드) (2026-10-06)

목적: 고정 스키마가 아니라 **실제 XGEN 저장소**(제품 빌드 그래프)에서도 하네스가 도는지,
그리고 같은 벤치에서 현행 제품 그래프가 어디에 있는지. lotteimall-dev 빌더도 술어를 자유롭게 만들므로
이 모드가 롯데 실동작의 전제다.

- 대상: 로컬 Fuseki `xgen` 데이터셋, `collection/wiki2_idfix3` — **같은 wiki2 3,000문서**를 XGEN 제품 파이프라인이 빌드한 그래프(66만 트리플)
- 방법(`harness/discover.py`): 개체-개체 술어 빈도 상위 80을 TBox 에서 읽어 계획기 카탈로그로 → 라벨 정규화로 상수·클래스 연결 →
  '수록된 항목' 은 표제 집합 사후 필터. 원자료 `results/d1_product.json`

## 판독

- 하네스는 **고정 스키마 없이 실제 제품 저장소에서 동작**한다(210문항 전부 실행, 인프라 오류 0).
- 관계 문항 0점의 원인은 그래프다: 술어 1,773종 가운데 **출생·국적·배우자·부모·자녀 술어가 아예 없다**
  (졸업·소속·설립·위치·사망은 있음). 오류 67건 중 53건이 계획기가 없는 술어(국적·출생…)를 고른 경우 — 0점으로 덮지 않고 사유 기록.
- 같은 문서에서 하네스 5차 ontokit 그래프(0.128)는 현행 제품 그래프(0.040)의 **3.2배**.

## 한계

- 제품 그래프는 과거 빌드(빌드 시점 ontokit 버전·설정 미확인)다. lotteimall-dev 의 LLM 빌더 그래프는 아직 재지 않았다
  (로컬에 lotteimall-dev 스택·데이터 없음).
- 사후 표제 필터는 ontokit 팔의 describes 한정과 같은 뜻이지만 구현이 다르다(라벨 기준).
