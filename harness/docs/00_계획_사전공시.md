# 온톨로지 하네스 — 계획·사전 공시 (2026-10-06)

> 이 문서는 **측정 전에** 작성·커밋한다. 판정 기준을 결과를 본 뒤 바꾸지 않는다(판례 K-1).
> 기준을 바꿔야 하면 새 문서에 사유와 함께 남기고, 이전 기준의 결과도 같이 보고한다.

## 1. 목적

graphstore(백엔드 교체 가능한 그래프 저장소) + ontokit(LLM-free·로컬 모델 추출) +
온톨로지 의미를 쓰는 질의 계층을 하나의 **온톨로지 하네스**로 묶고,
**열거·집계·관계·다중 홉 질문에서 벡터 검색보다 낫다는 것을 측정으로 보인다.**
최종 타깃은 lotteimall-dev(롯데아이몰) 실동작.

## 2. 가설 H1

타입·관계가 있는 그래프를 온톨로지 의미(하위 클래스 폐포·역관계·결합 조건)로 질의하면,
구조형 문항에서 벡터 검색(제품 검색 API, 상위 40)의 **상한**보다 정답 집합 점수가 높다.

## 3. 하네스 구성

```
질문 → planner(로컬 LLM, IR JSON) → compiler(IR → SPARQL; 5차에 Cypher)
     → graphstore(create_store: Fuseki RDF / Neo4j LPG) → 채점
그래프 공급: ontokit(KoELECTRA NER + KLUE-RE 인코더 v13c, LLM 0회) → 스키마 정렬 어댑터 → RDF
```

- 공통 스키마(`harness/schema.py`): 관계 12종(KLUE-RE 라벨 정본 + 위치 2종), 타입은 rdf:type(직업 포함)
- 질의 규칙: `x` 는 표제 개체로 한정, isa = `rdf:type/rdfs:subClassOf*`, 역관계 UNION
- **조용한 실패 금지**: 벡터 0건·SPARQL 빈 응답·적재 트리플 불일치·위키데이터 오류는 전부 예외

## 4. 벤치마크 (그래프를 보기 전에 고정)

- 코퍼스: wiki2 = 한국어 위키 리드 3,000문서(독립 문서 3,000, 단일 출처 유형 — 한계로 명시)
- 정답: **Wikidata 사실 중 해당 문서 본문에 실제로 적힌 것만**(2글자 라벨은 조사 경계 검사).
  도구 출력과 무관하다.
- 형태 7종(구조형 6 + 대조 1), 어느 형태도 30% 초과 금지:
  E1 타입 열거 / E2 계층 폐포 열거 / R 역관계 열거 / A 집계 / C 교차 조건 / M 다중 홉 / L 단순 조회
- 문항 파일 해시를 아래 §8 에 기록한다.

## 5. 팔(arm)

| 팔 | 내용 | 역할 |
|---|---|---|
| V40 / V100 | 제품 검색 API(text-embedding-3-small) 상위 40/100 — **상한 채점** | 기준 |
| G:oracle:gold | 정답에서 만든 그래프 + 정답 계획 | 양성 대조(하네스 유효성) |
| G:placebo:gold | 오라클의 누가-무엇을 전단사 치환 | 음성 대조 |
| G:ontokit:gold | ontokit 그래프 + 정답 계획 | 그래프 품질만 분리 |
| **G:ontokit:llm** | ontokit 그래프 + 로컬 LLM 계획기 | **처치(실사용 경로)** |
| G:oracle:llm | 오라클 + LLM 계획기 | 계획기 품질만 분리 |

벡터 상한: 정답 근거 문서가 상위 k 에 든 비율 R → F1_up = 2R/(1+R)(정밀도 1 가정), 집계는
근거가 전부 와야 1. LLM 이 아무리 잘 읽어도 이 값을 못 넘으므로 **벡터에 유리한** 비교다.

## 6. 판정 기준 (사전 공시)

- **측정 유효성**: oracle:gold 구조형 평균 ≥ 0.90, placebo:gold ≤ 0.15. 미달이면 그 차수 결과는
  무효로 보고하고 하네스부터 고친다.
- **"큰 차이"**: G:ontokit:llm − V40, 구조형 평균 Δ ≥ **+0.15** 이고 쌍 부트스트랩 95% CI 하한 > 0.
- **회귀 감시**: L(단순 조회)에서 G 가 V40 보다 크게 낮으면 하이브리드 라우팅을 다음 차수 과제로.
- 진행 규칙: 차수마다 **가장 큰 손실 구간 1개**를 표적·예상 Δ 와 함께 공시 → 수정 → 재측정 →
  문서화 → 커밋. 5차 안에 "큰 차이"가 나오면 5차에서 종료. 5차까지 미달이면 H1 검증 실패로
  기록하고 6~10차는 새 가설로 진행.

## 7. 측정하지 않는 것(현재)

- 실제 롯데 도메인 문서(자료 없음) — 커머스 대체 자료는 후속 차수
- 벡터+LLM 실제 답변 정확도(상한만 잼; 표본 실측은 후속)
- 응답 지연·비용(기록은 하되 판정 기준 아님)
