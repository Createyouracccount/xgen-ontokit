## 3. 손실 분해 (오라클 대비 남은 점수, 문항 합)

R 35.1 > E2 27.6 > A 26.0 > M 24.3 > C 22.6 > E1 20.9

- **R**: 40문항 중 위치 관계(loc:country·loc:located_in) 16문항이 **0점** — 위치 관계 재현율 0%(KLUE 라벨 부재)
- E2: 계층 폐포(가수 ⊂ 음악가 등)가 텍스트에 안 적힌 상위어라 정의문으로도 안 잡힘
- A: 개수 정확 일치는 재현·정밀 모두 완벽해야 함 — 구성원 F1 은 0.166 이지만 개수 정확 0/30

## 4. 4차 공시 (처치 전 고정)

- **표적**: R(최대 손실), 그중 위치 관계 0점 16문항.
- **처치**: LLM-free **위치 서술 관계 채널**(ontokit opt-in `ONTOKIT_LOC_REL=1`). 문서 주제 개체(2차와 같은 정의)에 대해
  주제 문장 안의 NER 지역 개체 Y 가 ⓐ "Y의 …" ⓑ "Y에 있는/위치한/소재한" ⓒ "Y 북부/남부/…" 로 서술되면
  주제가 인물이면 `per:origin(Y)`, 아니면 `loc:located_in(Y)`+`loc:country(Y)`
  (국가/행정구역을 텍스트만으로 구분 못 해 둘 다 낸다 — 질문 상수가 대상을 가르므로 정밀도 손실이 작다고 **가정**, 측정으로 확인).
- **지표·예상**: 위치 관계 재현율(eval) 0% → **≥ 15%**, R 0.122 → **≥ 0.20**, 구조형 **+0.02 이상**.

### 4-1. 공시 정정 (구현 착수 전, 측정 전)

위치 사실의 주어는 대부분 장소(도시·강·건물)인데 2차의 주제 정의(PER/ORG 만)를 쓰면 이 채널이 거의 발화하지 않는다.
→ 위치 채널의 주제 = **첫 문장 최선두 개체(날짜·시간·수량 클래스 제외)**. 2차 관계 인코더의 주제 정의는 그대로.
패턴 목록(ⓐⓑⓒ)·지표·예상치는 변경 없음.
