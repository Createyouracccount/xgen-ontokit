# 6차 — H2: 로컬 LLM 스키마 유도 추출 (2026-10-07)

처치: 문서마다 qwen3:8b(ollama, 외부 API 0) 1회 — 주제 개체의 {타입들, (관계키, 목적어)들}을 폐쇄 스키마(관계 12종)로.
ontokit 5차 그래프와 합집합(`harness/extract_llm.py merge`). 원자료 `results/r6.json`.

## 1. 모델 선택 (dev 전용, 80문서 두 묶음)

| 모델 | 관계 재현율 | 타입 재현율 | 속도 |
|---|---|---|---|
| qwen3:1.7b | 8.1% | 18.2% | 2.4초/문서 |
| **qwen3:8b** | 43.5% · 54.8% | 22.7% · 38.5% | 13.8초/문서 |

배선 결함 2건을 dev 에서 잡았다: ① qwen3 의 사고 모드가 출력 예산을 먹어 빈 응답(40건 중 34건) → `think:false`
② 모델이 개수 제한을 무시해 JSON 이 잘림(20%) → 마지막 완결 항목까지 살리는 복구 파서(복구 불가는 예외).

## 2. 전체 추출

3,000문서 43,914초(≈12.2시간, 같은 GPU 를 다른 측정과 나눠 쓴 구간 포함), 실패 4건(0.13%).

## 4. 판정 (사전 공시 R5 §6)

**H2 기준(+0.15, CI 하한 > 0): 미달** — +0.141 로 0.009 모자란다. 결과를 본 뒤 기준을 낮추지 않는다.
방향과 유의성은 확보됐다(CI 하한 +0.084).

## 5. 주의 — 이 수치를 일반화하지 않는 이유

- **오염**: 위키 리드는 LLM 사전학습에 들어 있을 가능성이 높다. 기억으로 맞힌 사실이 섞였을 수 있다
  (정답이 '본문 근거 사실'이라 기억 기반 출력은 대부분 오답으로 잡히지만, 완전히 배제되지 않는다).
- 연구계획서의 방법론(LLM 없이 결정적 구축)과 다르다 — 연구에서는 **품질 상한 참조점**으로만 쓴다.
- 비용: 3,000문서 약 12시간(로컬 8B, Mac). LLM-free ontokit 은 10분.
- 판정의 본선은 L00 루프(하이브리드 실답, 봉인 홀드아웃)다. 이 표는 그래프 단독·벡터 상한 비교다.
